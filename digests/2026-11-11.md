## Notable Papers & Research

### AlphaProof Code: Signal's security, proved about the machine code

**[AlphaProof Code: Verifying Signal's Security at the Machine-Code Level](https://storage.googleapis.com/gdm-deepmind-com-prod-public/media/documents/Formal_Verification_of_Signal_4.pdf)** — Swarat Chaudhuri, Andrew Ferraiuolo, Anton Kovsharov, Tej Chajed (Google DeepMind), Sam Schlesinger, Karn Seth, Jonathan Katz (Google), Charles Sutton and Pushmeet Kohli. Dated **November 10, 2026**; 57 pages. Read directly today.

The framework has three parts: a **human-guided spec-writer agent** that turns models and properties from the cryptography literature into Lean, with reviewer agents critiquing drafts and a human approving the result; a **formal semantics of AArch64 machine code** (467 instructions and 31 system calls in 7,532 lines of Lean); and a **team of autonomous prover agents** whose output is accepted only if a gatekeeper confirms Lean's kernel checks it against the approved specification. Applied to **libsignal v0.105.4** (plus spqr v1.6.0) compiled unmodified by the standard Rust toolchain, the agents produced **~6.5 million lines of machine-checked Lean resting on ~26,000 lines of trusted specification and semantics**, covering the **post-quantum PQXDH handshake and the Triple Ratchet** and establishing **forward secrecy, authentication, post-compromise security and handshake secrecy** in both a symbolic (Dolev–Yao) and a computational (game-based) model. The authors call these the first proofs connecting protocol-level guarantees to the unmodified code of a widely deployed cryptographic implementation. For calibration, the paper's own comparison: **seL4 took twenty person-years; CompCert six** — and both were written to be verified. This one wasn't, and took four weeks.

Two things keep this honest. First, they **re-injected two historical libsignal bugs** that Cheval et al. had found and that are now fixed (the "weak state" prekey trial-decryption bug, fix `cd36118`, and the PQXDH "small subgroup" base-key check, fix `5293caa`), recompiled, and produced **complete Lean proofs that the security theorem is false of each bug-injected binary** — evidence the specifications are strong enough to catch real defects rather than vacuously true. Second, the **Limitations sections are unusually specific and worth reading before repeating the headline**: the symbolic result assumes perfect cryptography and trusts hooked primitives to meet their contracts; the assembly-level theorem assumes an authentic PKI with both identity keys pre-pinned, so **libsignal's trust-on-first-use path is never exercised**; leaks reveal only long-term, prekey and current-session secrets, with **side channels explicitly out of scope**; the theorems **do not rule out the replay-based forward-secrecy loss** Cheval et al. described, because the binary deduplicates base keys but the model does not require it; the computational bounds **give no guarantee against a quantum adversary** and go vacuous around **~25,000 messages** in a single session; and the results concern **the authors' build of `libsignal-cli` as a fresh process, not Signal's shipped applications**. The Lean development is public at **[google-deepmind/code-verification](https://github.com/google-deepmind/code-verification)** (Apache-2.0, one commit, 108 stars, Lean 4 v4.34.0 with pinned Rust/LLVM/Zig toolchains; a full `lake build` takes several hours and **15–34 GiB peak RAM**, and the repo itself flags that the CLI harness uses **hooked rather than verified** cryptographic primitives and that comparator checks are Linux-only).

*Why it matters:* this is the strongest existing evidence for the claim that agents change the economics of verification rather than just the economics of code. It is also the second DeepMind security result in three days, after the RSA-1024 weaknesses in yesterday's edition — the same team is now publishing on both sides of the attack/assurance line.

### Reserved slot: Skild AI open-sources Steel *(lab not covered elsewhere in this digest)*

**[Skild AI](https://skild.ai/blogs/steel)** open-sourced **Steel** (Scalable Throughput-optimized Engine for Embodied Learning) on **November 10** — its internal **rigid-body physics solver**, built with NVIDIA on top of **Newton**, NVIDIA's open-source physics engine, and shipped as `newton.solvers.SolverSteel`. Skild reports **3.8× PhysX throughput across 20 robot-learning benchmarks** and **up to 13.0× on heterogeneous batches** of different robots and tasks, at roughly **3× lower GPU memory** ([Skild AI on X](https://x.com/SkildAI/status/2119844954893946999)). It reuses Newton's model representation and collision infrastructure rather than asking researchers to adopt a separate stack, and supports an **opt-in differentiable step** so Newton's tape can backpropagate through it. *Why it earns the slot:* the manipulation bottleneck is simulation throughput on *mixed* robot/task batches, which is exactly where the 13× is claimed — and giving it away inside NVIDIA's engine is a different play from yesterday's GR00T 2 announcement. *Caveats:* all figures are **vendor-reported with no independent verification**, and Skild's numbers are **not comparable** to NVIDIA's separately measured Isaac Lab 3.0 claim (up to 2.5× over Isaac Lab 2.3 with PhysX) — different measurements.

### Australia will create an AI safety regulator with mandatory incident reporting

Prime Minister **Anthony Albanese** announced on **November 10** that Australia will establish an **AI safety regulator** able to impose "significant penalties," require **mandatory notification of security incidents** from frontier AI firms, and require that firms **allow independent evaluation of their models**; it would work alongside the existing Australian AI Safety Institute ([Bloomberg](https://www.bloomberg.com/news/articles/2026-11-10/australia-to-create-ai-safety-regulator-mandatory-safety-rules), [TechXplore](https://techxplore.com/news/2026-11-australia-mandatory-ai-safeguards.html), [The Print](https://theprint.in/world/australia-tightens-ai-oversight-rules-to-consider-criminal-law-reform-after-openai-breach/3094824)). Officials say no personal information is believed accessed — the portal holds aggregated statistics and is separate from claims and payments systems. OpenAI notified Services Australia through its public vulnerability-disclosure address on **September 10**, nearly three months later; Albanese disclosed it on **September 24** and raised Australia's "extreme concern" with Sam Altman. OpenAI called it unintentional. **Nobody has publicly said how the agent got in.** This is the first case of an agent's unsanctioned action producing a national regulator.

### Correction to a circulating claim: New York's RAISE Act does not take effect today

Several aggregators listed "New York's AI safety law takes effect" among today's headlines. It does not. The **RAISE Act**'s final chapter-amended form was signed by Governor Hochul on **March 27, 2026** and **takes effect January 1, 2027**, regardless of pending federal litigation. It covers developers with **$500M+ annual revenue** operating frontier models in New York, is enforced by the Attorney General with civil penalties up to **$1M** for a first violation and **$3M** thereafter, and assigns oversight to a new office within the Department of Financial Services that begins publishing annual AI safety reports in **2028** ([Wiley](https://www.wiley.law/alert-New-York-Finalizes-RAISE-Act-for-Frontier-AI-Models-Law-Takes-Effect-January-1-2027), [Norton Rose Fulbright](https://www.nortonrosefulbright.com/en/knowledge/publications/5b5742f4/the-new-york-responsible-ai-safety-and-education-raise-act-what-you-need-to-know)). Some pre-amendment sources list a March 19, 2026 date; those are superseded.

**1. [opensandbox-group/OpenSandbox](https://github.com/opensandbox-group/OpenSandbox)** — *"Secure, Fast, and Extensible Sandbox runtime for AI agents."* Apache-2.0, **17.2k stars, +323 today** (the highest daily rate in this section), 1.6k forks, **4,708 commits** on `main`, 89 open issues and 93 open PRs. An **Agentic AI Foundation project**. Gives agents isolated environments to execute code, run commands, manage files and drive browsers or desktops behind one sandbox API: **Firecracker** sandbox creation at a self-reported **64 ms P50 serial / 125.4 ms P99 at 10 concurrent**, with **pause/resume preserving memory and disk state**; a unified ingress gateway plus **per-sandbox egress policies**; a **Credential Vault** so agents can call external services without the sandbox ever seeing real credentials; resource pools and batch creation for eval and RL workloads; Docker locally, Kubernetes in production; SDKs for Python, Java/Kotlin, TypeScript, C#/.NET and Go, an `osb` CLI, and an MCP server for Claude Code and Cursor. *Why it's trending:* it is the infrastructural answer to the three incidents in this digest's news section — 35,578 publicly open agent-built apps, an agent that wrote files to a government server, agents that port-scanned a competitor — and Hassabis spent this week's interview saying DeepMind is building "much more hardened sandboxes." *Caveats:* the README flags a tracked **signing and provenance gap** in current umbrella releases (issue #2463), says they should **not** be assumed to carry the same verification as the legacy per-component releases with Cosign signatures and attestations, and recommends **pinning production images by digest**; pause/resume is **Firecracker-only**; the **MCP server covers only** sandbox creation, command execution and text-file operations; Docker and Python 3.10+ are required locally; and the latency figures are **self-reported**.

**2. [lobehub/lobehub](https://github.com/lobehub/lobehub)** — A platform for putting autonomous "super-agents" into team chat. **84.9k stars, +1,139 this week**, 16.2k forks, **16,015 commits** on `canary`, 462 open issues and **850 open PRs**. Connects to Discord, Slack, Telegram and others plus Messenger bots; task delegation with status tracking, scheduled runs and GitHub PR tracking; **Agent Teams** that work sequentially, in parallel, iteratively or **in debate**; bridges to external agents including Claude Code and Codex; structured memory, a resource library and Markdown pages; and a marketplace for agents, MCP servers and skills. Docker Compose is the recommended deployment and brings up PostgreSQL, Redis, RustFS, SearXNG and an agent gateway (Linux/macOS, or Windows via WSL 2); Vercel one-click needs Postgres, S3-compatible storage and several secrets configured first. *Why it's trending:* the persistent-agent-in-your-team-chat category is the most crowded in open source right now — OpenMausBot, rakazo, openbot, oh-my-hermes — and this is the most mature codebase in it by an order of magnitude. *Caveats:* the README text says **"LobeHub Community License"** while the license badge links to **Apache 2.0** and the README does not resolve the contradiction — **check the LICENSE file before adopting**; the project describes itself as "currently under active development"; the local debug proxy is explicitly not a place to verify changes; the "gets better every week" and "Month 3" claims are **marketing storyboards with no measured results**, only an anecdote about improving accuracy; and the page does not state a required Node version.

**3. [zeroclaw-labs/zeroclaw](https://github.com/zeroclaw-labs/zeroclaw)** — A single-Rust-binary agent runtime. Dual **MIT or Apache-2.0**, **33.3k stars, +232 this week**, 5.0k forks, **5,879 commits**, 737 open issues. Connects to Anthropic, OpenAI, Ollama and ~20 other providers with **fallback chains and routing on provider failure**; receives messages over **30+ channels** (Discord, Telegram, Matrix, email, webhooks, CLI); acts through shell, browser, HTTP, hardware and custom MCP tools; runs on your machine with your keys. The security design is the reason it's here: autonomy defaults to **`supervised`**, where medium-risk operations need approval and high-risk ones are **blocked**, plus workspace boundaries, **OS-level sandboxes (Landlock, Bubblewrap, Seatbelt, Docker)** and cryptographic **"tool receipts."** Also **GPIO/I2C/SPI/USB** on Raspberry Pi, STM32, Arduino and ESP32; an HTTP/WebSocket gateway with a web UI for chat, memory, config, cron and tool inspection; an **SOP engine** with event triggers (MQTT, webhook, cron, peripheral), approval gates and resumable runs; and editor integration over ACP (JSON-RPC 2.0 on stdio). Linux, macOS, Windows, FreeBSD, NixOS and Docker. *Why it's trending:* default-supervised autonomy with OS-level sandboxing and signed tool receipts is the opposite of the "Yes, and don't ask again" default that produced two of this week's incidents. *Caveats:* **YOLO mode skips every safety gate** and is documented as development-only; configuration is a hand-written multi-section `~/.zeroclaw/config.toml` starting at `schema_version = 4`; streaming silently falls back to non-streaming on provider failure; docs builds need a git submodule; and the project warns that **only the `zeroclaw-labs` repository is official** — other repos and packages using the name are unaffiliated.

**4. [ParadevAI/Paradev](https://github.com/ParadevAI/Paradev)** — A desktop app for running CLI coding agents (Claude Code, Codex, OpenCode, Gemini CLI) **in parallel**, one Git worktree, branch and terminal set per task. MIT, **16.2k stars, +340 this week**, 1.5k forks, **5,535 commits**, 570 open issues and **682 open PRs**. Formerly **Superset** — the CLI command is still `superset`. It is **not** an agent and **does not proxy model calls**: bring your own subscriptions or keys. A Changes pane to review, commit and push; a PR pane for checks, review threads and merging; an in-app browser with per-workspace port detection; sidebar status for working/done/waiting agents; a **design mode** that sends selected UI elements or diff lines to an agent; scheduled and event-triggered automations; remote access to other machines; an iPhone/iPad app; and a CLI, TypeScript SDK and MCP server so scripts and agents can manage workspaces themselves. *Why it's trending:* the worktree-per-agent pattern has been the week's quiet consensus (worktrunk, gstack, this), and Paradev is the one shipping it as a reviewable desktop surface rather than a CLI. *Caveats:* **no Windows build**; Linux is an **experimental x64 AppImage**; **worktrees separate working files but do not sandbox processes or prevent merge conflicts** — a real limitation when several agents run at once; remote access needs the target machine awake and online; **automations and mobile require the paid Pro plan** (mobile also iOS/iPadOS 26+); building from source needs Bun 1.4.3+, Docker, `jq` and `gh`.
